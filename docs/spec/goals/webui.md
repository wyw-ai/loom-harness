# Loom Harness WebUI 目标与验收

官方 `webui@1.3.0` 在 `/webui/` 提供聊天与管理工作台。管理员可以通过页面发现 OI Service 并绑定给 Agent，普通用户可以从对话展开一次工具执行，核对回执、目标 Host 与 OI 调用号。这条链路已用真实 OIS、OIC、浏览器在 Windows 联验。[复现方法](../../../README.md#验证) · [当前目标](../../goal-shaping/current/webui/design.md) · [封板记录](../../goal-shaping/archive/webui/2026-11-24-product-scope/notes.md)

## 目标

交付一个能使用和管理整个 Loom Harness 的 WebUI。用户既能与 Agent 协作，也能找到自己有权管理的资源、查看当前配置，并核实一次修改或运行的实际结果。Agent 管理、插件管理和工具管理均属于核心范围。

## 已确认的产品范围

| 能力 | 用户应该能完成的事情 |
| --- | --- |
| Agent 与模板 | 从标准、创造者或插件模板创建 Agent，查看和修改 Agent spec、模型与系统指令，配置工具和工具集，核对最终生效的权限与工具。 |
| 插件 | 查看官方及已安装插件，管理包、版本、实例、启停和配置，了解插件提供了哪些工具、模板、订阅和扩展入口。 |
| 工具、Toolset 与连接 | 查找内置工具、插件工具、独立自定义工具和 MCP 工具，管理工具集及 Agent 绑定。OI 连接展示发现的每个 Service、成员和使用它的 Agent，可从该处授权、绑定并进入对话。 |
| Session 与对话 | 创建、切换和分支会话，使用附件、输入框推荐与流式回复，回答 Agent 的追问，断线后回到原会话。 |
| Run、Goal 与审批 | 查看运行进度，补充输入或取消，理解 Goal 为什么续跑或等待。具有审批权的用户能在相关调用上处理审批，并看到恢复执行的结果。 |
| 上下文、调用与原文 | 查看上下文预览、压缩及其来源，追溯实际发给模型的消息与系统指令。查看模型和工具调用、耗时、token 用量、工具回执、附件与 Note 原文。 |
| Event、Dispatch 与交付 | 从事件追踪到投递、Run 和最终回复，管理事件触发和定时调度规则，预览匹配结果，查看订阅处理与交付状态。 |
| 宿主、HOME 与扩展 | 按身份查看模型、资源目录、配置生效情况和诊断，发现当前安装插件提供的能力。宿主内部机制应体现为用户能观察、操作或排查的结果。 |

正式启动时，逐项核对各身份的 `GET /api/openapi.json`、Agent 工具和 HOME 配置，记下每项能力的使用者、操作入口和结果验证方式。对于目前只经 Agent 工具或 HOME 生效的能力，应写明受支持的操作方式及缺失的宿主接口。OI Service 自动导入依赖内部工具插件。[现有能力总览](../../design-review.md) · [服务规范](../README.md) · [内部工具接入规范](oi-workspace-tools.md)

## 产品与交互参考

- **学习 Codex 的产品设计。** 正式设计时，选取切换工作上下文、发起任务、跟进执行、查看细节、返回原处等完整流程，对照其信息层级、布局、导航、输入区和快捷键，再决定 Loom 用户怎样完成对应任务。
- **学习 Codex 的视觉语言和细节动效。** 连同页面布局一起研究字体、间距、色彩、选中与焦点状态，以及侧栏开合、详情展开、流式追加、等待和完成时的过渡。以用户能看懂状态变化、保持阅读位置为判断依据，同时考虑窄屏和减少动态效果的偏好。
- **保留 DSH 的聊天式自管理。** 用户可以直接在管理界面完成常规操作，也能在对话中让获授权的 Agent 执行修改。两种入口应能回到同一份真实资源，查到什么变了、是否生效、由谁执行。例如从 Agent 详情进入对话修改描述，再返回详情核实新值。

## 产品验收

会话的统计栏提供四项数据。

| 指标 | 计算与展示 |
| --- | --- |
| Token 消耗 | 按实际模型调用累计供应商回报的输入、输出和总 token。同一份历史随两次请求发送会产生两次输入消耗。压缩调用归入发起它的 Run，独立的输入框推荐只计入 Session。分支只计算在该分支实际发起的调用。 |
| 输出速度 | 流式请求优先显示首个输出至响应结束之间的生成速度；可测调用的输出 token 之和除以这些区间的总秒数。全程速度含模型首段等待。旧记录缺少可信的起止时间时仅展示已有的测量值。 |
| 自动压缩 | 按宿主实际使用的字节估算比较最近一次组装的模型输入与配置阈值。详情展示阈值、累计压缩次数、压缩前后大小及执行状态；正在生成摘要时显示「正在压缩」。 |
| 缓存 | 以有缓存回执的输入 token 为分母，将各次请求的命中数相加再求命中率；同时展示命中和未命中数。有输入但没有缓存回执时，命中率未知。 |

每个 Run 在对应回复旁及 Run 详情中显示累计输入输出消耗和从受理到终态的实际耗时。运行中展示已用时间。新请求的终态时间持久化，重连后可复核；只有秒级时间戳的旧 Run 按近似值展示。读取统计复用 Session 和 Run 的归属校验，不触发模型调用。

聊天区保留会话、草稿与执行过程；「工作台」汇总管理入口。Ctrl K（macOS 上为 ⌘ K）可跨两处查找当前身份可见的入口。输入框的 `/` 列操作及工具贡献的建议；`@` 从当前 Agent 有权调用的工具中插入模型名。对话中向上阅读时，后续流式输出保留当前位置，用户可以主动回到最新消息。参数、回执和 Run 详情可以从对应轮次逐步展开。完成的回复可复制原文或从所选回复分支，新会话的历史截至该回复。

工具可通过 `webui.suggestion` 声明简短标题 `label` 与草稿 `prompt`，去除首尾空白后分别限 64 和 1200 个 UTF-16 单元。建议必须来自 Agent 的生效工具目录，采用前再次核对授权，点击后保留编辑机会。比如绑定主机 Skill 的工具集后，空会话即可从「浏览主机 Skill」开始。[DSH 与 Loom 网页实测](../../acceptance/webui-comparison.md)

由验收人在浏览器中以相应身份操作，使用持久化资源、调用记录或另一端的实际结果复核。下表给出代表性场景，上述各组能力均需纳入覆盖清单。

| 场景 | 完成后要能核对的结果 |
| --- | --- |
| 管理 Agent、插件与工具 | 管理员配置并启用插件，能找到该实例提供的工具。从模板创建 Agent 并绑定获准的 Toolset 后，在首个 ModelCall 中查到对应工具。撤销授权后，服务端拒绝旧会话对该工具的新调用。 |
| 界面与聊天修改同一资源 | 在创造者 Agent 的详情中更改描述并重新打开。通过聊天让已获授 `agents.update` 的同一个创造者再次修改自己的描述。详情读到第二次修改的生效值，聊天记录能定位执行该修改的 ToolCall。 |
| 会话、等待与恢复 | 从含附件的会话发起 Run，查看流式回复。在请求补充信息或审批时，以相应身份响应。重新连接后能回到同一 Session，查到原 Run、等待原因与最终回复。 |
| 追查一次执行 | 从用户消息或 Event 找到 Delivery、Run、ModelCall 与 ToolCall，核对实际系统指令、请求与回复 token、首 token 时间和工具回执。自动转存的大结果能从 Session 或 Event 读回同一 Note 原文。 |
| 调度与配置生效 | 对事件触发和定时调度查看规则及预览，在运行记录核对匹配、投递及其结果。管理员应用 HOME 配置后能看到生效状态及配置诊断。 |
| 联合验收 | 创造者在聊天中读回 Host A 的 `workbench`，保留已有的 `capture_a`、`view_on_a` 等成员及访问规则，加入 `list_skills`、`read_skill`。授权用户在页面找到自动同步的 `oi-office.workbench` 并绑定给业务 Agent。该 Agent 能以发布名截图、读图并按引用读取 Host A 的 Skill。从页面的 ToolCall 能定位 OI 调用号、来源和结果。 |
| 连贯操作 | 在桌面和窄屏上切换会话、跟随流式输出、展开工具详情并返回，核对焦点、阅读位置及键盘操作。等待、失败和完成各有可辨认的反馈，启用减少动态效果时仍能判断状态。 |
