# 一次工具问答的逐消息时间线

2026-11-24，在本机用同一条消息分别跑默认配置和显式思考模式。用户问“请调用工具查询 T42 的 CI 报告，用一句中文告诉我错误码和所在行号。”。两次都由真实 `deepseek-flash` 发起一次 MCP `get_report("T42")`，读到测试 CI 返回的 `T42 failed: error E421, line 280.`，然后在第二轮回答。[每个模型和客户端数据帧的接收时间](evidence/tool-timeline-frames.csv)

同一轮的输入消息随单个 HTTP 请求一起发送。表里的整组接收时刻是本机观测器读完该请求体的时间，DeepSeek 服务端没有返回逐条输入消息的接收时间。显式思考样本中，Loom 在 +503.753 毫秒收到首段推理。上游推理分片从首段到末段横跨 **248.831 毫秒**，从首段推理到出现工具名共 270.543 毫秒。DeepSeek 提供的是分片和 token 计数，模型内部推理的起止时钟不可见。

默认样本的工具调用从登记到登记回执约 **31 毫秒**，显式思考样本约 **21 毫秒**。其中 MCP 测试端读取完请求到开始写回结果正文分别为 0.063 和 0.065 毫秒。本次的 CI 查询读取固定报告。SQLite 观察点取自事务内插入事件的毫秒钟，与高精度 HTTP 时间戳比较时可能有约一毫秒的先后偏差。

## 模型调用前后用了多少 token

| 配置和轮次 | 本轮输入 | 本轮输出 | 其中推理 | 本轮回复后总计 | 截至本轮的累计用量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 默认 · 第 1 轮，生成工具调用 | 354 | 45 | 0 | 399 | 399 |
| 默认 · 第 2 轮，生成答案 | 439 | 23 | 0 | 462 | **861** |
| 显式思考 · 第 1 轮，生成工具调用 | 354 | 64 | 19 | 418 | 418 |
| 显式思考 · 第 2 轮，生成答案 | 458 | 22 | 0 | 480 | **898** |

上述计数均取自 DeepSeek 响应中的 `usage`，并与 Loom 的 ModelCall 记录逐轮核对。输入列是发起调用时那批消息与工具定义的实际 `prompt_tokens`，准确值随响应返回。每轮总计是 `prompt_tokens + completion_tokens`，推理 token 已含在输出中。累计用量包含下一轮重新提交的历史。显式思考样本第二轮的 458 个输入 token 中，有 256 个命中提供方缓存。[DeepSeek 用量字段定义](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)

运行环境为同机 API 和单个 worker、release 构建 `b2e0a55`、SQLite 和 Redis Streams。为取得上游逐帧时刻，测试链路加入一个本机透明 SSE 转发器，第二个样本由转发器在出站请求中显式设置 `thinking.type=enabled`。两次独立运行各自从新的上游连接开始，第二轮复用该连接。以上为两个单次观测；热连接短问答的延迟分布见[首 token 基准](first-token.md)。
