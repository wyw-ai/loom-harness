| 用例 | 观察结果 |

| C05 主动续跑与恢复 | 阶段总结后原 Run 续跑，后续按证据调用完成工具并交付。另一组在续跑请求出站时终止 Loom 并重启：Run `run_81007e1b49a44dbab1cb4b94744eb4e5` 中一条 `model_call_cfd37b2dcdbc48f885f9e55d744acc07` 对应两次提供方请求。辅助模型每次生成不同的摘要标记，两次出站消息仍完全相同。续跑输入中有且仅有一条来源为 Goal 的用户角色说明；真实聊天中没有增加用户续跑发言。 |

| C07 失败回执唤醒 | 长迁移历史在 CI 受理前已发生压缩，失败分析时也使用压缩历史。向 `tool_call_70a72425f16648b386a6c946bccc4cf1` 重送同一报告；分析调用 `model_call_b1c6fd98903a4286b0f581259cc12af0` 的触发原因是工具回执，输入具备目标、完成条件和 FAIL-42，主动续跑说明数为 0，原 CI ToolCall 数为 1。 |

**复跑方式。** 构建服务后将 `LOOM_TEST_BIN` 指向待验二进制，将 `LOOM_TEST_REDIS_URL` 指向测试 Redis，再运行 `python tests/acceptance_context.py -v`；设置 `LOOM_TEST_TRACE=1` 可以输出本次生成的对象 ID。客户端时序用 `node --test tests/composer.test.mjs`，模型响应、Note 及历史选取的模块测试用 `cargo test --locked context::`。每次测试结束会清理临时 HOME，表中的 ID 用于对照该次记录。

**覆盖边界。** C03 将窗口超限、尚未完成的 CI、进度问询和最终回执组合在同一个 HTTP 用例。C04、C11 核对的持久摘要来自父 ModelCall 保存的实际输入。C13 在同一台机器更换服务进程并保留 HOME。C14 验证了提供方实际收到截图字节，OCR 识别结果由受控提供方给出；自然视觉模型的识别准确率需独立测量。
